# Деплой

Как Graveshift собирается, проверяется и выкатывается на сервер. Ни адреса сервера, ни домена в
репозитории нет: они живут в секретах GitHub Environment и в `.env` на самом сервере.

## Схема

```
push в master
  └─ CI: pnpm check ─ docker build ─ Trivy ─ push в GHCR (тег = SHA, + SBOM и provenance)
       └─ Deploy (environment: production)
            └─ ssh deploy@<DEPLOY_HOST> deploy ghcr.io/…@sha256:…
                 └─ /opt/graveshift/bin/deploy.sh: blue-green переключение

Сервер:  :80/:443 ─ Caddy (TLS Let's Encrypt, HTTP/3) ─┬─ blue:8686   ← активный слот
                                                        └─ green:8686  ← следующий релиз
```

## Что разрулено и зачем

### Образ

| Решение                                                | Зачем                                                                    |
| ------------------------------------------------------ | ------------------------------------------------------------------------ |
| Многоэтапная сборка: клиент, прод-зависимости, рантайм | в итоговом образе нет исходников клиента, dev-зависимостей, pnpm и кэшей |
| `node:24-alpine`, закреплён по digest                  | маленький образ; сборка воспроизводима, база не меняется молча           |
| `apk upgrade` в рантайм-слое                           | закрывает CVE, исправленные в Alpine после выхода базового образа        |
| npm, npx, corepack, yarn удалены из рантайма           | это самый частый источник CVE в node-образах, а в рантайме они не нужны  |
| Пользователь `node`, файлы принадлежат root            | процесс не может переписать собственный код                              |
| `tini` как PID 1                                       | сигналы доходят до Node, зомби-процессы собираются                       |
| `HEALTHCHECK` на `/api/health`                         | Docker и деплой знают, когда контейнер реально готов                     |
| Версия = SHA коммита (`GRAVESHIFT_VERSION`)            | `/api/health` показывает, что именно сейчас в проде                      |

### Рантайм (`deploy/compose.yaml`)

- `read_only`, `tmpfs /tmp`: файловая система контейнера только для чтения. Исключение — общий
  именованный том `admin-data` в `/app/data` для SQLite с админскими настройками обоих слотов.
- `cap_drop: ALL`, `no-new-privileges`: у игрового сервера нет никаких Linux capabilities.
  Caddy оставлен только `NET_BIND_SERVICE`.
- Лимиты `mem_limit`, `cpus`, `pids_limit`: игра не съест память соседних сервисов.
- Логи идут в journald (`tag: graveshift-…`). Хранение по времени (3 дня) настраивается на
  хосте в journald, а Docker сам ограничивать логи по времени не умеет.
- `restart: unless-stopped`: контейнеры поднимутся после перезагрузки сервера.

### Деплой без простоя и без обрыва матчей

Матчи живут в памяти процесса, поэтому простой перезапуск убил бы все идущие игры. Вместо этого:

1. `deploy.sh` поднимает новый релиз в свободном слоте (blue ↔ green) и ждёт `healthy`.
   Если не поднялся, старый слот продолжает работать, деплой падает.
2. Старый слот получает `SIGTERM`, и сервер переходит в режим `draining`:
   - `/api/health` отвечает `503`, Caddy за ~2 с перестаёт слать туда новые запросы;
   - игроки в меню (не в комнате) отключаются и сами переподключаются уже к новому релизу;
   - идущие матчи доигрываются: открытые WebSocket-соединения Caddy не рвёт.
3. Когда закрылась последняя комната (или прошло `GRAVESHIFT_DRAIN_SECONDS`, в проде 15 минут),
   старый процесс завершается сам.

Ограничения:

- Друг, который заходит по коду в комнату старого релиза во время дренажа, попадёт на новый
  релиз и получит «комната не найдена».
- Если следующий деплой придёт раньше, чем закончился дренаж, недоигранный слот будет остановлен.
  Матчи в нём прервутся.

### Доступ CI к серверу

- **Отдельный пользователь.** CI заходит под `deploy` с отдельным ключом ed25519.
  У пользователя заблокирован пароль, и он не входит в группу `docker`.
- **Ключ умеет только одно.** В `authorized_keys` у ключа стоят опции
  `restrict,command="/opt/graveshift/bin/ssh-gate.sh"`. Шелла, проброса портов, агента и PTY нет.
  Гейт принимает ровно одну команду: `deploy <образ@sha256:…>`.
- **sudo только на деплой.** В sudoers разрешён только `/opt/graveshift/bin/deploy.sh`.
  Скрипт принадлежит root, и `deploy` не может его изменить.
- **Только наши образы.** `deploy.sh` пропускает только `IMAGE_REPOSITORY@sha256:<digest>`.
  Чужой образ или плавающий тег не выкатить.
- **Отпечаток хоста закреплён.** Он лежит в `DEPLOY_KNOWN_HOSTS`, поэтому
  `StrictHostKeyChecking=yes` и подмену сервера ssh не пропустит.
- **Токен реестра одноразовый.** Для `docker pull` деплой передаёт `GITHUB_TOKEN` джоба через stdin.
  Токен живёт до конца джоба, на сервере пишется во временный `DOCKER_CONFIG` и сразу удаляется.
- **Инфраструктуру CI не меняет.** Изменения `compose.yaml`, `Caddyfile` и скриптов CI выкатить
  не может: их ставит человек через `deploy/push-infra.sh`.

### CI (`.github/workflows/ci.yml`)

- **Права.** `permissions: {}` по умолчанию; каждому джобу выдан минимум: `packages: write` только
  у сборки, `packages: read` у деплоя.
- **Сторонние actions** закреплены по SHA коммита. Dependabot обновляет actions, базовые образы
  (`Dockerfile` и `deploy/compose.yaml`) и npm-зависимости. Он берёт только релизы старше 3 дней
  (`cooldown`): за это время успевают отозвать скомпрометированные версии, а pnpm не блокирует
  слишком свежие. Мажорные версии `typescript` и `@types/node` обновляются вручную.
- **Trivy** роняет сборку на уязвимостях `HIGH` и `CRITICAL`, для которых уже есть исправление.
- **Еженедельная пересборка** без кэша по понедельникам подтягивает свежие патчи Alpine и выкатывает их.
- **SBOM и provenance** прикладываются к образу в GHCR.
- **Деплой** идёт только из `master`, последовательно (`concurrency: production`) и через
  environment `production`. В нём можно включить ручное подтверждение.
- **Проверка после выката:** `/api/health` по публичному адресу должен вернуть версию, равную
  SHA коммита.

## Первая настройка

### 1. Ключ для CI

```bash
ssh-keygen -t ed25519 -N '' -C graveshift-ci -f graveshift-ci
```

### 2. Сервер

Нужны Docker с compose-плагином и пользователь с sudo. Из корня репозитория:

```bash
DEPLOY_PUBLIC_KEY="$(cat graveshift-ci.pub)" \
GRAVESHIFT_DOMAIN=<домен> \
IMAGE_REPOSITORY=ghcr.io/baldpippins/graveshift \
deploy/push-infra.sh <ssh-хост>
```

Скрипт идемпотентный: он создаёт пользователя `deploy`, раскладывает файлы в `/opt/graveshift`,
пишет `.env` с правами 600, настраивает sudoers и поднимает Caddy. Повторный запуск без
переменных просто обновит `compose.yaml`, `Caddyfile` и скрипты, а `.env` и ключ не тронет.

DNS-запись `A` домена должна смотреть на сервер, а порты 80 и 443 должны быть открыты.

### 3. GitHub

Settings → Environments → `production`:

| Тип      | Имя                  | Значение                                                     |
| -------- | -------------------- | ------------------------------------------------------------ |
| secret   | `DEPLOY_HOST`        | адрес сервера                                                |
| secret   | `DEPLOY_USER`        | `deploy`                                                     |
| secret   | `DEPLOY_SSH_KEY`     | содержимое приватного `graveshift-ci`                        |
| secret   | `DEPLOY_KNOWN_HOSTS` | вывод `ssh-keyscan -t ed25519 <адрес>`, сверенный с сервером |
| variable | `PUBLIC_URL`         | `https://<домен>`                                            |

После этого удалите локальный приватный ключ. Рекомендуется защита ветки `master`: мерж только при
зелёном джобе `Check`.

### Админ-панель и хранение настроек

Панель доступна по `/admin.html` и использует ключ из `GRAVESHIFT_ADMIN_KEY`. Без ключа API
недоступно. Укажите в `/opt/graveshift/.env` ключ из 32–128 символов `A-Z`, `a-z`, `0-9`, `_`, `-`;
случайный ключ можно создать командой `openssl rand -hex 32`. Храните его как секрет и передавайте
администраторам защищённым каналом. После изменения `.env` пересоздайте игровые слоты через
обычный деплой; смена ключа отзовёт старый доступ после замены слота. В продакшене используйте HTTPS.

В Compose `GRAVESHIFT_TRUST_PROXY=1` доверяет заголовкам от частных, loopback и link-local адресов
для ограничения попыток входа по IP. Caddy по умолчанию не доверяет входящим `X-Forwarded-*`.
Не публикуйте порт игрового сервера напрямую и допускайте в его внутреннюю сеть только доверенные
сервисы: иначе заголовок с адресом клиента можно подделать.

`GRAVESHIFT_ADMIN_DB=/app/data/admin.sqlite` указывает на общий том `admin-data`. Оба слота читают
настройки и обновляют их без перезапуска; файл переживает пересоздание контейнеров. Если в новой
версии нет ни одной включённой карты, её health-check вернёт `503`: деплой оставит старый слот.
Включите в работающем слоте карту, присутствующую в новой версии, и повторите деплой. При резервном
копировании используйте согласованную SQLite-копию с учётом WAL, а не копируйте только основной файл
работающей базы. Удаление тома удалит настройки доступности карт.

Для локальной разработки задайте `GRAVESHIFT_ADMIN_KEY` перед запуском `pnpm dev`; база по умолчанию
лежит в игнорируемой Git директории `.graveshift/`. `GRAVESHIFT_ADMIN_DB` позволяет выбрать другой
путь. В production при заданном ключе постоянный путь обязателен.

## Повседневное

| Задача                         | Как                                                                          |
| ------------------------------ | ---------------------------------------------------------------------------- |
| Выкатить                       | push в `master`                                                              |
| Выпустить версию               | сам после мержа, см. [releases.md](releases.md)                              |
| Откатить                       | Actions → Rollback → образ `ghcr.io/…@sha256:…` из лога прошлого деплоя      |
| Обновить compose/Caddy/скрипты | `deploy/push-infra.sh <ssh-хост>`                                            |
| Что сейчас в проде             | `curl https://<домен>/api/health`                                            |
| Логи                           | `sudo docker compose --project-directory /opt/graveshift logs -f blue green` |
| Активный слот                  | `sudo cat /opt/graveshift/state/active`                                      |
| Ход дренажа                    | `sudo cat /opt/graveshift/state/drain-<slot>.log`                            |

## Локальная проверка образа

```bash
docker build --build-arg VERSION=local -t graveshift:local .
docker run --rm -p 8686:8686 --read-only --tmpfs /tmp --cap-drop ALL \
  -e GRAVESHIFT_DRAIN_SECONDS=30 graveshift:local
```

`docker kill -s TERM <контейнер>` во время матча покажет дренаж: `/api/health` вернёт `503`, а
процесс выйдет, когда закроется комната.
